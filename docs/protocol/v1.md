# Amadeo agent protocol, version 1

**Status:** in use · **Transport decided by:** `adr/0016` · **Version constant:**
`amadeo_agent::PROTOCOL_VERSION`

This is the engine's only control surface. The CLI speaks it, the editor will speak it (invariant
I5), and an agent can speak it directly. Nothing gets a privileged path.

---

## Where it runs

A **game binary** hosts the server. It has to: under ADR 0011 a game's components are Rust types
compiled into that binary, so nothing else can describe them.

```text
mygame --amadeo-agent [--ticks N]
```

`amadeo-cli` does this for you, via `cargo run -p <game> -- --amadeo-agent`, so the binary is
rebuilt if stale.

## Framing

**One JSON request per line in, one JSON reply per line out.** No content-length headers, no
batching, no notifications. A request can be typed at a prompt; a transcript can be read with `cat`.

**stdout is the protocol.** Anything a game prints there corrupts the stream. Diagnostics go to
stderr.

Blank input lines are skipped. Input ending is what ends the session.

## Envelope

JSON-RPC 2.0. Request:

```json
{"jsonrpc": "2.0", "method": "world.query", "params": {"components": ["Transform"]}, "id": 1}
```

`params` may be omitted, and must be an **object** when present — this server takes named arguments,
never positional ones. `id` is echoed back untouched, whatever its type.

Reply, one or the other:

```json
{"jsonrpc": "2.0", "result": {...}, "id": 1}
{"jsonrpc": "2.0", "error": {"code": -32601, "message": "..."}, "id": 1}
```

Object keys in every reply are **sorted**, so a dump can be committed and diffed without the order
churning.

### Error codes

The reserved JSON-RPC range, meaning what the spec says:

| Code | Meaning |
|---|---|
| `-32700` | the request was not valid JSON |
| `-32600` | valid JSON, not a valid request |
| `-32601` | no such method — the message lists every method there is |
| `-32602` | the method exists, the arguments were wrong |

Every message is written to be actionable on its own. An agent reading one cannot ask a follow-up
question, so "no component named `Velocty` is registered. Registered: Player, Quad, Transform,
Velocity" is the standard, not "not found".

## Determinism

**One invocation is one fresh deterministic run.** How far to simulate is `--ticks` at launch, not a
method, so every question in a session sees the same world and the same command twice gives the same
answer twice. That is what lets a question an agent asks become a test it writes.

Every method in version 1 is **read-only**. Looking at a world cannot change it.

## Methods

### `describe`

The component schema, generated from the code — never stale, never a guess.

| Param | Type | |
|---|---|---|
| `type` | string | optional; one type instead of all of them |

```json
{"jsonrpc":"2.0","method":"describe","params":{"type":"Velocity"},"id":1}
```

Returns `name`, `docs`, `kind`, `version`, and `fields` — each with `name`, `type`, `docs`, and any
`unit`, `range`, or `replication` metadata. The whole-schema form also carries `protocol_version`.

### `world.list`

Every live entity, in a stable order, plus the current `tick`. The thing to call first.

### `world.entity`

One entity's components and their values.

| Param | Type | |
|---|---|---|
| `entity` | integer | **required**; slot index, as reported by `world.list` |

A stale index is an error, not an empty dump.

### `world.query`

Entities carrying **all** of the named components.

| Param | Type | |
|---|---|---|
| `components` | array of strings | filter; empty matches everything |

Naming an unregistered component is an error rather than an empty result — "there are none of those"
and "that component does not exist" are different answers, and confusing them is exactly the
plausible-but-wrong failure Pillar 2 exists to eliminate.

### `world.resources`

Every resource in the world, as an object keyed by type name. Takes no parameters.

```json
{
  "count": 3,
  "resources": {
    "Camera2d": { "center": [0.0, 0.0], "height": 10.0 },
    "InputState": { "axes": {}, "buttons": {} },
    "SimRng": { "increment": 1, "state": 6364136223846793006 }
  }
}
```

The other half of "what is in this world": entities carry components, and everything else is a
resource. Sorted by name — a resource id is a hash, so its ordering is reproducible but in a sequence
no reader could predict.

An **object rather than an array of pairs**, because a caller almost always wants one specific
resource and `resources.SimRng` beats scanning a list. Names are unique by construction.

Reading a resource cannot perturb it: `to_value` observes state rather than consuming it, which
matters most for `SimRng` — drawing a number to inspect a generator would change the thing being
inspected.

> **Known gap: `InputState`'s keys are unreadable.** They are `ActionId`s, and an `ActionId` is the
> hash of an action's name with the name not kept, so this reports `"8831028638596390904"` rather
> than `"move_x"`. Faithful and useless. The names exist in the input driver — that is how a
> `.replay` file writes readable action names — but they sit outside `InputState` deliberately, since
> a resource is part of the state hash and two runs registering different names for the same actions
> must not diverge. Filed as **Q18**; the fix belongs here, at the presentation layer.

### `snapshot.take`

The whole world as `.snapshot` text. Takes no parameters.

```json
{
  "tick": 600,
  "state_hash": "ad2c2fee76cbbd1c",
  "entities": 16,
  "resources": 3,
  "text": "amadeo-snapshot 1\ntick 600\n..."
}
```

Returns **text, not a path**. The game knows what the world is; the CLI is the side that touches the
filesystem — the same division `scene.check` and `assets.list` use.

**There is no `snapshot.restore` to match, and that is not an oversight.** Restoring has to happen
before the first tick, so it is the `--snapshot <path>` *launch* argument instead — the same shape,
and the same reason, as `--replay`. By the time a method could be called the pre-roll has already
run, and the moment the snapshot was meant to replace is gone.

The two compose. `--snapshot mid.snapshot --ticks 30` lands on the recorded moment from a file and
then runs thirty more, which is the whole point: ADR 0011 measured re-simulation at ~21 µs/tick,
growing linearly with session length.

Capturing cannot perturb the world — reading a resource observes its state rather than consuming it,
which matters most for `SimRng`.

See `docs/adr/0028` for the format, and for why it records the entity allocator's free list.

### `schedule.list`

Systems in **resolved execution order**, per stage, with whether the stage is inside the
deterministic zone.

| Param | Type | |
|---|---|---|
| `stage` | string | optional; one of `PreSimulation`, `Simulation`, `PostSimulation`, `Render`, `Present` |

### `scene.check`

Validates a scene against the game's real component schema — the thing a standalone tool cannot do.

| Param | Type | |
|---|---|---|
| `text` | string | **required**; the scene file's contents |

**The text is sent, not a path.** The game process has no business reading the client's filesystem,
and a path would resolve relative to wherever the game was launched, which is not where the user
typed it. The client reads the file; the game, which holds the registry, judges it.

Returns `ok`, `entities`, and `diagnostics` — **every** problem, not the first. An agent fixing a
scene cannot ask a follow-up question, so one error per round trip is a functional defect.

A syntax error comes back in the same shape as a schema error, so a client handles one thing rather
than two. Syntax diagnostics carry `line`; schema diagnostics carry `entity` and usually `component`,
and a client holding the source text can turn an id into a line (`amadeo check` does).

### `replay.status`

The result of the replay this process was launched with. Takes no parameters — the replay is a
**launch argument**, not a method, and has already run by the time this can be called.

```text
mygame --amadeo-agent --replay <path> --seed <n>
```

Returns `passed`, `path`, `seed`, `ticks`, `checked`, and `mismatches` — each carrying `tick`,
`expected`, and `found` as hex strings. It does **not** stop at the first mismatch: "60 and 300
diverged but 180 did not" is a far more useful fact than "60 diverged".

Calling it in a process launched without `--replay` is an error saying so, not an empty pass.

**Two launch arguments, and why they are not method parameters.** A replay has to be installed
before the first tick, so by the time any method could be called it would be too late. The seed is
worse: `App::with_seed` fixes it at construction, which happens before the agent handover is even
reached — so a game that wants to be replayable reads `amadeo_app::requested_seed()` *before*
building. A game that does not gets a clear seed-mismatch error rather than a mysterious divergence.

### `assets.list`

Every asset the game knows about, by the id a scene refers to it by. No parameters.

```json
{"jsonrpc":"2.0","method":"assets.list","id":1}
```

```json
{
  "installed": true,
  "count": 2,
  "root": "C:/Users/justi/Desktop/Personal/Amadeo/assets",
  "root_anchor": "project-marker",
  "assets": [
    {"id": "placeholder", "source": "textures/placeholder.ppm", "state": "resident",
     "bytes": 700, "settings": {"filter": "nearest"}},
    {"id": "wall_concrete", "source": "textures/wall_concrete.ppm", "state": "catalogued"}
  ],
  "unimported": [],
  "orphaned": []
}
```

**This method is a requirement of ADR 0020, not a convenience.** Naming an asset by a declared `id`
rather than by its path costs an agent the ability to list a directory and reference what it sees —
the id lives inside a sidecar. The ADR names this method as the mitigation and requires it to exist
*before* ids become the reference syntax, so that authoring a scene means looking an id up rather
than guessing one.

| Field | Meaning |
|---|---|
| `installed` | whether the game scanned a catalogue at all; `false` gives an empty listing plus a `note` rather than an error, since a game with no assets is ordinary |
| `source` | the file, relative to `root`, **always with forward slashes** so a reply is identical on Windows and Linux |
| `state` | `catalogued` (the id is known) or `resident` (the bytes are in memory) |
| `bytes` | present only when resident |
| `root_anchor` | which rule found the asset directory: `project-marker`, `executable`, or `working-directory` (ADR 0022) |
| `unimported` | asset files with no `.ama-meta` sidecar, so not referenceable — the papercut ADR 0020 predicted, reported so the error can explain itself |
| `orphaned` | sidecars whose asset file is gone |
| `failures` | present only when something failed to load; each entry is an `id` and a `message` |

**A failed load is reported here rather than raised.** ADR 0021 requires a missing asset to produce
a visible stand-in and a structured report instead of a crash, because an agent's only eyes are the
protocol — so the game keeps running and this is where the problem is visible.

`state` is deliberately reported even though ADR 0021 forbids *gameplay* from observing it. An agent
inspecting from outside the simulation is not gameplay, and is exactly who needs to know.

### `sim.status`

`tick`, `state_hash`, `events`, `components`.

**`state_hash` is a string of 16 hex digits, not a number.** It is a `u64`, and JSON numbers are
`f64` — above 2^53 a client would silently read a different value, which would break replay
assertions in the least visible way available.

## Not in version 1

Deferred deliberately, not forgotten. ADR 0016 defers the first group until M4's editor needs a
connection that outlives one question; the rest wait on subsystems that do not exist yet.

- **Mutation and control:** `sim.step`, `sim.pause`, `sim.set_speed`, `world.spawn`, `world.despawn`,
  `world.set_component`, `input.inject`. These need a persistent session.
- **`events.since(tick)`** — needs event history retained past the double buffer.
- **`scene.load` / `scene.save`** — needs prefab resolution, which is blocked on reconciling what
  `from` holds: ADR 0014's grammar says a path, ADR 0020's example says an asset id, and the two
  have not been squared. `scene.check` exists and needs neither, because it is handed the text.
- **`render.capture` / `render.describe`** — the agent's eyes. Needs the 2D renderer, which needs Q3.
- **`snapshot.diff`** — comparing two snapshots. (`snapshot.take` is implemented; see above.
  Restoring is the `--snapshot` launch flag rather than a method, deliberately — ADR 0028.)
- **`replay.record`** — recording a session from inside agent mode. Playing one back exists
  (`replay.status`); recording still needs a live input source, which batch mode does not have.
- **`profile.frame`** — needs a profiler. (`assets.list` and `world.resources` were both in this
  list and are now implemented; see above. `world.resources` was blocked on `Resource: Reflect`,
  which ADR 0027 delivered.)

## Changing this document

The version constant is bumped when a method changes shape in a way an existing client would notice.
Adding a method is not a breaking change; changing what an existing field means is. `describe`
reports `protocol_version` so a client can check rather than assume.
